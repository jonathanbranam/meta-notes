*meta-notes.txt*    Personal note-taking and life management system

                                                *meta-notes*
META-NOTES HELP ~

A vim plugin for personal organization using plain-text markdown files,
following the PARA (Projects, Areas, Resources, Archives) folder structure.

1. INTRODUCTION                                 *meta-notes-intro*

meta-notes is a life management solution that stores all notes as plain-text
markdown files. It is inspired by Tiago Forte's "Building a Second Brain" and
Cal Newport's multi-scale planning.

The system organizes notes into five top-level folders: plan, project, area,
resource, and archive. See |meta-notes-folders|.

==============================================================================
2. SETUP                                        *meta-notes-setup*

Add to your `.vimrc`: >
    set runtimepath+=/path/to/meta-notes
<
Then initialize the folder structure in your notes root directory: >
    :MetaNotesInit
<
or from a shell, in the notes root (see |meta-notes-cli-init|): >
    meta-notes init
<
To force re-creation of template files: >
    :MetaNotesInit!
<
Notes roots created before `.meta-notes` existed should be initialized once
more so the CLI can find them (see |meta-notes-cli-root|). Re-running is
safe: only missing items are created.
Set your local leader if not already set: >
    let maplocalleader = ","
<

==============================================================================
3. FOLDER STRUCTURE                             *meta-notes-folders*

The PARA structure uses five top-level folders:

    plan/           Planning notes (daily, weekly, quarterly, yearly)
      daily/        Daily notes with time blocks and task lists
      week/         Weekly planning notes
      quarter/      Quarterly planning notes
      year/         Yearly planning notes

    project/        Active projects with specific goals and end dates
    area/           Areas of ongoing responsibility
    resource/       Reference materials on topics of interest
    archive/        Archived items
      project/
      area/
      resource/

Daily notes are organized into quarter subfolders to limit folder size: >
    plan/daily/26-Q1/2026-02-13 Thu.md
    plan/week/26-Q1/2026-02-09.md
    plan/quarter/2026-Q1.md
    plan/year/2026.md
<

==============================================================================
4. COMMANDS                                     *meta-notes-commands*

------------------------------------------------------------------------------
INITIALIZATION ~

                                                *:MetaNotesInit*
:MetaNotesInit[!]
    Initialize Vim's current directory as a notes root: the PARA folders,
    default templates, the `.meta-notes` sentinel, and links to the plugin's
    skills. Only missing items are created. With [!], overwrites existing
    template files and replaces skill targets that aren't links. Runs
    `meta-notes init`; see |meta-notes-cli-init|.

------------------------------------------------------------------------------
NAVIGATION ~

                                                *:MetaNotesOpen*
:MetaNotesOpen
    Follow the wiki-style link under the cursor. Opens or creates the note
    referenced by `[[path/to/note]]`. If the note does not exist, opens a
    new, unsaved buffer with a template or default header, rendered by
    `meta-notes note new` (|meta-notes-cli-note|).
    See |meta-notes-wiki-links|.

                                                *:MetaNotesDaily*
:MetaNotesDaily [{date}]
    Open today's daily note, or the daily note for {date} (YYYY-MM-DD format).
    Daily notes are stored at: `plan/daily/YY-QN/YYYY-MM-DD ddd.md`

    Example: >
        :MetaNotesDaily
        :MetaNotesDaily 2026-01-15
<
                                                *:MetaNotesDailyPrev*
:MetaNotesDailyPrev
    Navigate to the previous existing daily note. Must be in a daily note
    buffer. Shows a message if already at the oldest note.

                                                *:MetaNotesDailyNext*
:MetaNotesDailyNext
    Navigate to the next existing daily note. Must be in a daily note buffer.
    If at the newest note, prompts to create the next day's note.

                                                *:MetaNotesJumpToWeek*
:MetaNotesJumpToWeek
    Jump from the current daily note to its corresponding weekly plan note.
    Must be in a daily note buffer.

                                                *:MetaNotesWeekPlan*
:MetaNotesWeekPlan [{date}]
    Open the weekly plan note for the current week, or the week containing
    {date} (YYYY-MM-DD format). The file path uses the Monday of that week.
    Stored at: `plan/week/YY-QN/YYYY-MM-DD.md`

    Example: >
        :MetaNotesWeekPlan
        :MetaNotesWeekPlan 2026-02-09
<
                                                *:MetaNotesQuarterPlan*
:MetaNotesQuarterPlan [{date}]
    Open the quarterly plan note for the current quarter, or the quarter
    containing {date} (YYYY-MM-DD format).
    Stored at: `plan/quarter/YYYY-QN.md`

                                                *:MetaNotesYearPlan*
:MetaNotesYearPlan [{date}]
    Open the yearly plan note for the current year, or the year containing
    {date} (YYYY-MM-DD format).
    Stored at: `plan/year/YYYY.md`

------------------------------------------------------------------------------
FILE OPERATIONS ~

                                                *:MetaNotesArchive*
:MetaNotesArchive [{path}]
    Archive a file or folder. Without {path}, archives the current buffer's
    file. {path} can include wildcards (`*`, `?`) for batch archiving.

    Moves items preserving their subfolder structure:
        `project/item`  →  `archive/project/item`
        `area/item`     →  `archive/area/item`
        `resource/item` →  `archive/resource/item`

    Also updates all wiki-links and file headers across the notes directory.
    If the current buffer is the archived file, switches to the new location.

    Only works on items in `project/`, `area/`, or `resource/`.

    Examples: >
        :MetaNotesArchive
        :MetaNotesArchive project/old-project
        :MetaNotesArchive project/2024-*
<
                                                *:MetaNotesRename*
:MetaNotesRename [{new-name}]
    Rename the current note. Without {new-name}, prompts for the new name.
    {new-name} can be just a filename (preserves current directory) or a full
    path (moves the file to a new location).

    Updates wiki-links and headers automatically.

    Examples: >
        :MetaNotesRename
        :MetaNotesRename new-filename
        :MetaNotesRename project/new-location/filename
<
                                                *:MetaNotesMoveItem*
:MetaNotesMoveItem {source} {destination}
    Move a file or folder from {source} to {destination}. Updates all
    wiki-links and headers across the notes directory.

    Example: >
        :MetaNotesMoveItem project/foo area/foo
<
------------------------------------------------------------------------------
TIME TRACKING ~

                                                *:MetaNotesTimeReport*
:MetaNotesTimeReport
    Generate and display a time tracking report for the current daily note.
    Must be run from within a daily note buffer.
    See |meta-notes-time-tracking|.

------------------------------------------------------------------------------
DEVELOPMENT ~

                                                *:MetaNotesReload*
:MetaNotesReload
    Reload all plugin scripts without restarting vim. Useful during plugin
    development.

                                                *:TestMetaNotes*
:TestMetaNotes
    Run the full plugin test suite using vader.vim. Requires vader.vim to be
    installed. See |meta-notes-setup|.

==============================================================================
5. KEY MAPPINGS                                 *meta-notes-mappings*

All mappings use `<localleader>`. Set it with: >
    let maplocalleader = ","
<
Global mappings (all file types): ~

    <localleader>mr     Reload the plugin (|:MetaNotesReload|)

Markdown mappings (buffer-local): ~

    <localleader>l      Follow wiki link under cursor (|:MetaNotesOpen|)
    <localleader>n      Open today's daily note (|:MetaNotesDaily|)
    <localleader>np     Navigate to previous daily note (|:MetaNotesDailyPrev|)
    <localleader>nn     Navigate to next daily note (|:MetaNotesDailyNext|)

==============================================================================
6. TEMPLATES                                    *meta-notes-templates*

When opening a note that does not exist, meta-notes creates the file with a
template if one is defined for that note type, or a plain `# Title` header
otherwise. Templates are populated with the note's date and other contextual
information automatically.

Templates are rendered by `meta-notes note` (|meta-notes-cli-note|), so a
note created from a shell or by an agent gets the same content as one opened
in Vim. Vim asks the CLI for the rendered content and opens it as a new,
unsaved buffer: nothing is written until you save it.

Templates are created by |:MetaNotesInit| and stored in the notes root.

------------------------------------------------------------------------------
TEMPLATE RESOLUTION ~                       *meta-notes-template-resolution*

When a note is created, the template is chosen in this priority order:

1. `--template {name}`: `meta-notes note new {path} --template {name}` uses
   `resource/template/{name}.md` and skips the rest. It is an error if that
   file doesn't exist.

2. Folder-specific template: a file named `template.md` in the same
   directory as the note being created.
   Example: `project/kitchen-remodel/template.md` is used for every new
   note inside that folder.

3. Standard template for plan folders, chosen by the note's path: >
       plan/daily/   → resource/template/daily.md
       plan/week/    → resource/template/weekly.md
       plan/quarter/ → resource/template/quarterly.md
       plan/year/    → resource/template/yearly.md
<
If no template is found, the new note starts with a plain header: `# Daily
Note - YYYY-MM-DD ddd`, `# Week Plan - YYYY-MM-DD`, `# Quarterly Plan - YYYY
QN`, `# Year Plan - YYYY`, or `# {path}` for other notes.

YAML frontmatter (lines between `---` delimiters starting on the first line
of the template file) is stripped and does not appear in the created note.

------------------------------------------------------------------------------
TEMPLATE VARIABLES ~                        *meta-notes-template-variables*

Variables are written as `{{name}}` inside the template and are replaced
with their values when the note is created.

Date variables ~                            *meta-notes-template-date-vars*

Date variables support optional day-offset arithmetic and strftime format
specifiers. Without a format specifier the default output is `YYYY-MM-DD ddd`
(e.g. `2026-06-19 Fri`).

    date            The note's canonical date (YYYY-MM-DD): the day for a
                    daily note, the Monday for a weekly note, the first
                    day of the quarter or year for quarterly and yearly
                    notes, and today for other notes
    today           Today's actual date (YYYY-MM-DD)
    week_start      Monday of the note's week (YYYY-MM-DD)
    week_end        Sunday of the note's week (YYYY-MM-DD)

Arithmetic — add or subtract whole days: >
    {{date+7}}          seven days after the note date
    {{week_end-2}}      two days before the end of the week
<
Format specifiers — any strftime conversion. Day and month names are
always English, whatever the locale: >
    {{today:%A}}            full weekday name, e.g. Friday
    {{date:%B %-d, %Y}}     e.g. June 19, 2026
    {{date+7:%Y-%m-%d}}     arithmetic combined with a custom format
<
Path variables ~                            *meta-notes-template-path-vars*

Path variables are plain strings derived from the path of the note being
created. Arithmetic and format specifiers do not apply to them.

    note_path       Relative path without extension
                    e.g. `project/lunch/Lunch Ideas`
    note_name       Filename stem (no path, no extension)
                    e.g. `Lunch Ideas`
    filepath        Relative path with extension
                    e.g. `project/lunch/Lunch Ideas.md`
    filename        Filename with extension, no path
                    e.g. `Lunch Ideas.md`

Other variables ~

    quarter         Quarter string derived from the note date, e.g. `Q2`
    week_quarter    Quarter string of `week_start`, the Monday of the note's
                    week, e.g. `Q1` for a note dated 2026-04-02 (whose
                    Monday is 2026-03-30). Week plans are filed under the
                    quarter of their Monday, so use this, not `quarter`, in
                    week plan paths. The daily template links to its week
                    plan with: >
                        [[plan/week/{{week_start:%y}}-{{week_quarter}}/{{week_start:%Y-%m-%d}}]]
<
    project_name    Second path component for notes under `project/`,
                    e.g. `lunch` for `project/lunch/note.md`.
                    Empty string for notes outside `project/`.

Unknown variables produce an HTML comment: >
    <!-- ERROR: Unknown variable "name" -->
<
------------------------------------------------------------------------------
COMMAND BLOCKS ~                            *meta-notes-template-commands*

A template line containing `{{% type command %}}` is replaced, as a whole
line, by the output of that command when the note is created. Template
variables are substituted in the command string before execution. Commands
run from the notes root, with their stderr included in the output.

    {{% python script.py %}}    run a Python script with the Python running
                                `meta-notes`; a path starting with
                                `scripts/` is the plugin's scripts/ dir
    {{% shell command %}}       run any shell command
    {{% vim :Command %}}        run a Vim command; insert its output

Example — insert the tasks due on the note's date: >
    {{% python scripts/find_tasks.py --due-on {{date:%Y-%m-%d}} --condensed %}}
    {{% shell git log --oneline -5 %}}
    {{% vim echo "Created " . strftime('%H:%M') %}}
<
`{{% vim %}}` blocks run only when a note is opened in Vim. `meta-notes note`
substitutes the variables in the block and leaves it in its output, and
Vim runs it when it fills the new buffer. A note created outside Vim (for
example by `meta-notes note` without `--render`) keeps the block as text,
and the CLI warns about it.

A failed command is replaced with an HTML comment that includes the error,
and `meta-notes note` reports a warning. An unknown type is replaced with
`<!-- Unknown command type: {type} -->`.

==============================================================================
7. TIME TRACKING                                *meta-notes-time-tracking*

Daily notes support a time log format for tracking how time is spent. Use
|:MetaNotesTimeReport| to generate a report from the current daily note's
time log entries.

The report is only available when editing a daily note
(`plan/daily/YY-QN/YYYY-MM-DD ddd.md`).

Time log format ~
                                                *meta-notes-time-log*
Entries live under a `### Log` heading and end at the next heading. Each
entry is an activity line starting with `-`, optionally with tags, followed
by indented `*` detail lines: >
    ### Log

    - email review #admin
      * start: 08:15
      * end:   09:00
    - standup #mtg
      * start: 9:00am
      * end:   9:20am
      * any other detail line is a note
<
`start:` and `end:` accept these timestamp formats, which may be mixed
within a note and within an entry:

    `09:10`                  bare 24-hour time
    `3:20pm`, `3:20 pm`      bare 12-hour time
    `2026-02-14 08:00`       full date
    `2026-02-14 Sat 08:00`   full date with day abbreviation

A bare time takes its date from the `YYYY-MM-DD` in the note's filename, so
bare times only work in notes named with a date. A full date uses its own
date, which lets an entry end after midnight: `* end: 2026-02-15 01:30`. The
day abbreviation is not checked against the date.

A timestamp in any other form, such as the template's `HH:MM` placeholder,
leaves that time unset. The entry is kept but has no duration.

==============================================================================
8. WIKI LINKS                                   *meta-notes-wiki-links*

Notes can link to each other using Obsidian-style wiki links: >
    [[path/to/note]]
<
Place the cursor anywhere within the brackets and press `<localleader>l` (or
run |:MetaNotesOpen|) to open or create the linked note.

Paths are relative to the notes root directory and should not include the
`.md` extension.

Examples: >
    [[project/kitchen-remodel/Tasks]]
    [[area/health]]
    [[resource/vim-tips]]
<
When a note is moved, renamed, or archived, all wiki-links pointing to it are
updated automatically across the entire notes directory.

==============================================================================
9. COMMAND LINE                                 *meta-notes-cli*

`bin/meta-notes` runs the same file operations and task query as the plugin,
so notes can be reorganized from a shell, by an agent, or by other tools. The
plugin's |:MetaNotesArchive|, |:MetaNotesRename|, and |:MetaNotesMoveItem|
commands call it, |:MetaNotesInit| calls `meta-notes init`, and
|:MetaNotesDaily|, |:MetaNotesWeekPlan|, |:MetaNotesQuarterPlan|,
|:MetaNotesYearPlan|, and |:MetaNotesOpen| call `meta-notes note`. It needs
Python 3.10 or newer as `python3` on your `PATH`.

Put it on your `PATH`; the Claude Code skills call it by name. Link it into
any directory on your `PATH`: >
    ln -s /path/to/meta-notes/bin/meta-notes ~/bin/meta-notes
<The script follows the link back to the plugin, so the link keeps working
when a plugin manager updates the plugin.
Commands ~
                                                *meta-notes-cli-commands*
`meta-notes init [--root {dir}] [--force]`      *meta-notes-cli-init*
    Initialize a notes root: the PARA folders, the templates in
    `resource/template/`, the `.meta-notes` sentinel, and a link in
    `.claude/skills/` to each skill the plugin ships in `skills/`, so
    updating the plugin updates the skills. Initializes `--root` if given,
    creating it if missing, otherwise the current directory. It ignores
    `META_NOTES_ROOT`. Run it in the top-level directory of the notes root,
    for example right after `git init`.

    Re-running is safe: existing folders, templates, notes, and the sentinel
    are kept. A skill link to the right place is kept, and a broken or
    foreign one is repointed. A real file or directory at a skill's link path
    is left alone with a warning. With `--force`, templates are overwritten
    and those skill targets are replaced.

    Notes roots never nest: init fails if a directory above the target is a
    notes root (found the same way as |meta-notes-cli-root|).

    The skills call `meta-notes` by name, so init warns, with the `ln -s`
    command to fix it, when no `meta-notes` is on your `PATH`.

`meta-notes move {source} {dest}`
    Same as |:MetaNotesMoveItem|.

`meta-notes rename {source} {new-name}`
    Same as |:MetaNotesRename| for the note at {source}. A {new-name} without
    `/` keeps the note's directory; `.md` is appended if missing.

`meta-notes archive {path} ...`
    Same as |:MetaNotesArchive|. Quote wildcards (`'project/2024-*'`) so the
    CLI expands them; each match is archived independently and failures are
    reported per item.

`meta-notes note daily|weekly|quarterly|yearly [{date}] [--render]`
`meta-notes note new {path} [--template {name}] [--render]`
                                                *meta-notes-cli-note*
    Create a note from its template (|meta-notes-templates|) and print its
    path. {date} is any day in the note's period, as YYYY-MM-DD, and
    defaults to today. Periodic notes go where the Vim commands put them: >
        plan/daily/YY-QN/YYYY-MM-DD ddd.md
        plan/week/YY-QN/YYYY-MM-DD.md       (the week's Monday)
        plan/quarter/YYYY-QN.md
        plan/year/YYYY.md
<   `new` creates the note at {path} inside the notes root, appending `.md`
    if missing. A plan note's template date is taken from its name, and
    other notes use today.

    An existing note is never changed: the command just prints its path.
    With `--render`, nothing is written and no folder is created: the
    rendered note is printed instead, or, if the note exists, nothing is
    printed and `Note already exists: {path}` goes to stderr.

    Example: >
        meta-notes note daily
        meta-notes note weekly 2026-04-02 --render
        meta-notes note new project/trip/Packing --template checklist
<
`meta-notes tasks [options]`
    List tasks. Takes the same options as `scripts/find_tasks.py`
    (`--folder`, `--due-on`, `--due-by`, `--due-between`, `--status`,
    `--format`, `--condensed`) and prints the same output.

The CLI changes only the working tree. It never stages or commits.

Notes root ~
                                                *meta-notes-cli-root*
Paths in arguments and output are relative to the notes root, which is the
first of:
    1. `--root {dir}`
    2. the `META_NOTES_ROOT` environment variable
    3. the nearest directory, starting from the current one, that contains
       the `.meta-notes` sentinel created by |meta-notes-cli-init|

The upward search checks each directory only for `.meta-notes`. It stops
after `$HOME`, and stops quietly at the first directory you can't read,
write, and enter. If it finds nothing, the command fails and suggests running
`meta-notes init` or passing `--root`. An explicit `--root` or
`META_NOTES_ROOT` is used as given, with or without a sentinel.

The plugin always passes `--root` with Vim's current directory.

Output ~
                                                *meta-notes-cli-json*
Output is human-readable text by default, with errors and warnings on stderr.
With `--json`, every command writes exactly one JSON object to stdout and
nothing to stderr, whether it succeeds or fails: >
    {"ok": true, "moves": [...], "links_updated": [...], "warnings": []}
    {"ok": false, "error": "Source not found: project/foo.md", "warnings": []}
<
`move` and `rename` return `source`, `dest`, `moves` (`[old, new]` pairs),
and `links_updated` (files whose wiki-links were rewritten). `archive` adds
`items` with a result per archived path. `tasks` returns `tasks`, each with
`file`, `line`, `text`, `status`, `start`, `due`, `completed`, and, without
filters, the report `category`. `note` returns `path`, `exists` (whether the
note existed before), `created` (whether this command wrote it), and
`template` (the template used, or null); with `--render` and a new note, it
also returns `content`, the rendered note. Output from template commands
appears only in `content` or the written note, never on stdout.

The exit status is non-zero on failure. `--root` and `--json` may come
before or after the command name.
