Reported by the notes advisor, 2026-10-06 (notes m-0122): 'time-log append ... --start ~21:55' fails with "invalid time: '~21:55'; use HH:MM or 9:15am". conventions.md, Editing the Time Log: 'A tilde before a time means approximately: ~9:00 for the start or end.' Confirmed by the orchestrator on v2.26.4.

Change (scripts/meta_notes/time_log.py, spec design/specs/time-log-edit.md): --start and --end on append (and --prev-start, and --close-prev's written end) accept a leading '~' on either time form (~21:55, ~9:15am) and write it as '~HH:MM'. Comparisons (end not before start, --prev-start matching the last entry's start) use the time without the tilde; decide and state whether --prev-start '21:55' matches a stored '~21:55' (recommended: yes, the tilde doesn't change the time). Check that time-log update's --text validation accepts '* start: ~21:55' too, and that the time report (scripts/time_tracking.py) already reads tilde times; fix only if it doesn't. Spec, --help, doc/meta-notes.txt. Tests for append with a tilde start, a tilde end, and close-prev. Patch version bump.

Verify: ./run_tests.sh green; the append above by hand in a temp root, then 'meta-notes time' on that note.
Model: haiku. Out of scope: tildes in the Time Block.
