The repo side is done: dotfiles-local main at 99d657c has .bridle/config.toml (prefix dl, integration main, no standing manager), the sync output and .gitignore entries. `bridle doctor` passes. I also switched its origin to SSH (git@github.com:jonathanbranam/dotfiles-local.git), since HTTPS pushes had no credentials.

Run these in a terminal outside Claude Code: `!` inside a session carries BRIDLE_AS.

## On nuc

1. In ~/.bridle/config.toml, under [projects], add:
       dotfiles-local = { machine = "nuc", port = 7403 }
2. Start the daemon, the same way you run meta-notes':
       cd /srv/shared/work/dotfiles-work/dotfiles-local && bridle serve
   (add --detach to run it in the background; it logs to /srv/shared/work/dotfiles-work/.bridle/daemon.log). The first start creates your human token in /srv/shared/work/dotfiles-work/.bridle/tokens/human.
3. Create the orchestrator's token (it's saved to ~/.bridle/credentials.toml as [orchestrator] dotfiles-local):
       bridle token create orchestrator --project dotfiles-local
   Optional, only if you want advisors on it:
       bridle token create advisor --project dotfiles-local
4. Create the visitor token for dalek's orchestrator. It's printed once, so copy it for dalek:
       bridle token create orchestrator --machine dalek --project dotfiles-local

## On dalek

5. In ~/.bridle/config.toml, under [projects], add:
       dotfiles-local = { machine = "nuc", port = 7403 }
6. In ~/.bridle/credentials.toml (chmod 600), paste the token from step 4:
       [orchestrator.nuc]
       dotfiles-local = "<token from step 4>"
   (Add the key to the existing [orchestrator.nuc] table if there is one.)

When you're done, tell me and run `bridle task done <this id>`. Then I'll start watching dotfiles-local's daemon from the meta-notes orchestrator session (one orchestrator for every nuc project) and tell dalek's orchestrator about the new project.
