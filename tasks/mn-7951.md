1. Review bridle-adopt (2 commits): .bridle/config.toml (no manager, no orchestrator supervision), .bridle/roles/orchestrator.md (the life-admin instructions), .gitignore, and the .meta-notes sentinel.    cd /srv/shared/work/notes-work/notes && git switch main && git merge --ff-only bridle-adopt && git push origin main

2. Register the project in ~/.bridle/config.toml on the NUC, under [projects]:
   notes = { machine = "nuc", port = 7404 }
   and the same line in dalek's ~/.bridle/config.toml, as you did for dotfiles-local.

3. Put meta-notes on PATH (the skills and the role call it by name):
   ln -s /srv/shared/work/meta-notes-work/meta-notes/bin/meta-notes ~/.local/bin/meta-notes

4. After the bridle `just install` finishes, start the daemon in a new tmux window:
   cd /srv/shared/work/notes-work/notes && bridle serve

5. Create the orchestrator's token for it (only you can create tokens):
   cd /srv/shared/work/notes-work/notes && bridle token create orchestrator --project notes
   Optional, so advisors can write there: bridle token create advisor --project notes

6. Optional: add to the notes repo's CLAUDE.md (it's yours; nothing was changed in it):
   Run `meta-notes prime` at the start of every session and follow it.

Then tell the orchestrator. It runs `bridle doctor`/`status --project notes` to verify and starts handling notes requests; the NUC's single orchestrator covers notes too (no second orchestrator: bridle keeps one orchestrator pid file per machine).
Finish with `bridle task done <this id>`.
