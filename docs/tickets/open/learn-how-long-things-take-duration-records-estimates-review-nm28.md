# Learn how long things take

The human, 2026-10-03 (relayed by the notes advisor). The advisor planned
45 minutes to mow; the human lives on 7 acres and it takes 2-3 hours.

> basically I want to get better at remembering how long things take, and
> that's also a record for you to use to plan my events.

- Asked to "add a task to mow the lawn", the agent looks up how long mowing
  takes and plans with it.
- Records of how long kinds of things take, for the human and for planning.
- Like software estimation: estimate (t-shirt size), learn when wrong,
  "adjust our velocity". Like Pomodoro: predict three pomodoros, see it
  took five or two, update the prediction.
- A review step: "what kinds of things did you do this week? Do we have
  records for how long those kinds of things take?" and update them.
  Weekly at work (meta-notes `weekly-review`), maybe monthly at home.

## Through bridle

> This should be using bridle because that's part of the point of this
> exercise is for us to expand that system. We can make short-term fixes if
> we want, but the goal is for all of this to run through bridle in the
> end. So this would be like a rule or a skill that you invoke. Probably a
> skill that's based on rules is what I would target.

He expects to work out the design with the agents.

## Shape, to explore with the human

- Where the records live (a resource note, one note per kind, or data the
  CLI reads) and how a kind of activity is matched.
- Where the actuals come from: the Time Log already measures durations.
- The skill, its rules, and which part is bridle's and which meta-notes'.
- The review hook in `weekly-review` (and a monthly home review).

Stopgap: `resource/How Long Things Take.md` in the notes repo (mowing
2-3 h, a few measured durations from the time log).
